## 三、提交前检查清单

### 3.1 仓库设置

- [ ] 仓库位于**个人 GitHub 账号**下（组织仓库不行）
- [ ] 仓库为 **Public 公开**
- [ ] 仓库**创建时间**在 2025-12-25 ~ 2026-10-25 23:59 之间
- [ ] `.gitignore` 已生效（`.workbuddy/`、`mcp.json`、`__pycache__` 等不入库）
- [ ] 仓库名与项目名一致或高度相关

### 3.2 安全复核（官方会用 GitHub API 逐文件扫描）

- [ ] 无真实 MCP Token（`scripts/mcd_call.py` 从 `~/.workbuddy/mcp.json` 读取，不硬编码）
- [ ] `mcp-config.example.json` 只含 `${MCD_MCP_TOKEN}` 占位符
- [ ] 无手机号、账号 ID、收货地址、真实姓名
- [ ] `docs/`、`tests/`、`workbuddy.md` 中的个人信息已脱敏
- [ ] `.workbuddy/memory/` 已通过 `.gitignore` 排除

### 3.3 内容合规

- [ ] 不含违法违规、敏感、政治相关内容
- [ ] 不含赌博、色情、暴力、歧视内容
- [ ] 不含恶意代码 / 后门 / 钓鱼链接
- [ ] **不贬低麦当劳品牌**，不做竞品对比性贬损
- [ ] 明确标注「非麦当劳官方产品」（README 与 CONTEST_DECLARATION 均有）

### 3.4 文件完整性

```bash
# 一键自检
python - << 'EOF'
import os, re, json, hashlib
need = ["README.md","CONTEST_DECLARATION.md","MCP_INTEGRATION.md",
        "mcp-config.example.json","workbuddy.md"]
for f in need:
    print(("✅" if os.path.exists(f) else "❌"), f)
# 官方声明零差异
official = "91a7b32ec28098b609ca3f215cdf7147"
local = hashlib.md5(open("CONTEST_DECLARATION.md","rb").read()).hexdigest()
print(("✅" if official==local else "❌"), "CONTEST_DECLARATION 与官方一致")
# 配置脱敏
s = json.dumps(json.load(open("mcp-config.example.json",encoding="utf-8")))
print(("✅" if not re.search(r"Bearer\s+(?!\$\{)[A-Za-z0-9]{10,}", s) else "❌"), "配置仅占位符")
EOF
```

## 四、报名 Issue 格式（**格式校验极严格**）

在活动仓库发布 Issue：
https://github.com/M-China/mcd-developer-innovation-challenge/issues

**Issue 标题**（自定义）

**Issue 正文**（严格按此格式，注意换行要求）：

```
【参赛申请】
项目名称：mcd-ordering 麦当劳一句话点餐
项目地址：https://github.com/williamyi-666/0921
项目简介：基于麦当劳 MCP 能力的一句话点餐 Skill。用户说出人数、忌口和预算，自动完成定位门店、领券、搭配、择优用券、场景校验、算价，确认后下单并交付支付二维码与订单确认单。菜单无法满足忌口时明确告知而非静默替换。
```

### ⚠️ 三个极易踩的坑

1. **【标题】和【正文】之间不要有换行符**
2. **【项目名称】和名称内容之间不要有换行符**（同理每个字段）
3. **项目地址不要用 Markdown 格式**（不要写成 `[链接](url)`）
4. Issue 内容**不超过 1000 字**，不要带图片

> 官方提示：报名 Issue 的校验逻辑较为严格，不符合格式会直接失败。
> 失败后系统会在 Issue 下回复原因，修改后可重新提交。

**这是唯一影响排名的因素。** 没有评审打分，没有人工评优 —— 就是比 Star。

可行的自然增长方式：

- 项目本身够实用，值得分享（README 已带"使用示例"，可直接贴给同事）
- 发到技术社区（掘金、知乎、V2EX、GitHub Trending）
- 在 PR / Issue 里被引用

**禁止**：刷 Star、用小号或多账号互刷 —— 官方规则明确将"操纵 Star 数据"列入违规，
可直接取消资格并取消奖励。

## 七、常见失败原因

| 现象 | 原因 | 解决 |
|---|---|---|
| Issue 报名失败 | 格式不符（换行/换行符/Markdown 链接）| 严格按第四节模板，字段间不加换行 |
| 报"缺少必要文件" | 文件名写错或缺失 | 文件名一字不可改，见第二节 |
| 报"仓库不是 Public" | 仓库可见性 | 改为 Public |
| 报"创建时间不符" | 仓库创建太早或太晚 | 必须 2025-12-25 ~ 2026-10-25 |
| 报"内容含敏感信息" | 仓库里有 Token/个人信息 | 跑第 3.2 节复核 |
| 报名成功但没进榜 | **Star 数为 0** | 唯一的决定性变量，需主动传播 |
| 被取消资格 | 刷 Star / 抄袭 / 内容违规 | 见第五节 |
